# Design and build a distinctive UI grounded in its product brief

## When
Use when building a new UI or reshaping an existing one that needs an intentional visual direction rather than templated defaults.

## Material
A design brief identifying the product or subject, its audience, and its primary job. If the brief does not identify the subject, the Skill proposes and confirms one before designing.

## Done
A reviewed design plan with color, typography, layout, and distinguishing principles, followed by UI code that remains responsive, keyboard accessible, visually accessible, and respectful of reduced motion.

## Requires
A brief to review the plan against. Screenshot-based self-critique is used when the environment supports screenshots.

## Replaces
Default visual choices that repeat across unrelated briefs, including generic card kits, stock hero treatments, and typography or decoration that does not serve the product's subject.
