# 驗證結果

這份紀錄整理三輪實驗：檢索、候選後反問、作者那一側的 description 改寫。數字取自 `experiment/report.json`、`experiment/ask/report-*.json`，以及 `experiment/desc/` 的 picks 與 `score.py` 計算結果。實驗樣本彼此獨立，不能把不同輪的命中率直接當成同一組查詢的差異。

## 1. 檢索：description、完整文件、工作線卡、BM25

75 條查詢，五類各 15 條。A 嵌入原始 description；B 嵌入 `SKILL.md` 前 4,000 字；C 嵌入工作線卡；D 對完整 `SKILL.md` 使用 BM25。

| 條件 | Recall@5 | 第一名命中率 | 近誤率 |
|---|---:|---:|---:|
| A：description | 0.827 | 0.453 | 0.307 |
| B：SKILL.md 前 4,000 字 | 0.867 | 0.467 | 0.280 |
| C：工作線卡 | 0.773 | 0.493 | 0.227 |
| D：BM25 | 0.480 | 0.293 | 0.080 |

第一名命中率按類別：

| 類別 | A | B | C | D |
|---|---:|---:|---:|---:|
| API development | 0.667 | 0.667 | 0.667 | 0.333 |
| Frontend design | 0.200 | 0.267 | 0.333 | 0.267 |
| SEO | 0.600 | 0.667 | 0.667 | 0.467 |
| Social media publishing | 0.400 | 0.333 | 0.467 | 0.333 |
| Test automation | 0.400 | 0.400 | 0.333 | 0.067 |

結論：C 的第一名命中率最高，但 Recall@5 最低，且各類別並非一致領先；B 的 Recall@5 最高。D 的近誤率最低，但其餘檢索指標明顯較弱。因此不能宣稱工作線卡整體優於 description 或完整文件。

限制：只有 75 條查詢；近誤率只看第一名是否為標註的近誤；類別內候選高度相似；工作線卡主要由固定規則從上游文字抽取，結果只代表這個實作，不代表所有人工撰寫卡片。

## 2. 反問：直接搜尋與看候選後追問

20 條模糊需求。`direct` 是原始模糊需求；`targeted` 使用看工作線卡後的針對性回答；`raw_targeted` 是使用只看原始 description 所產生問題的針對性回答；`generic` 是固定通用問題的回答；`full_intent` 直接提供完整需求，作為參考上界。

| 條件 | Arm | Recall@5 | 第一名命中率 | 近誤率 |
|---|---|---:|---:|---:|
| A：description | direct | 0.850 | 0.500 | 0.250 |
| A | targeted | 1.000 | 0.750 | 0.200 |
| A | raw_targeted | 1.000 | 0.750 | 0.100 |
| A | generic | 0.900 | 0.800 | 0.150 |
| A | full_intent | 0.950 | 0.700 | 0.050 |
| B：SKILL.md 前 4,000 字 | direct | 0.950 | 0.400 | 0.300 |
| B | targeted | 0.950 | 0.650 | 0.250 |
| B | raw_targeted | 1.000 | 0.700 | 0.200 |
| B | generic | 0.900 | 0.700 | 0.150 |
| B | full_intent | 0.850 | 0.650 | 0.100 |
| C：工作線卡 | direct | 0.800 | 0.450 | 0.100 |
| C | targeted | 0.950 | 0.700 | 0.200 |
| C | raw_targeted | 0.900 | 0.700 | 0.050 |
| C | generic | 0.800 | 0.650 | 0.200 |
| C | full_intent | 0.900 | 0.800 | 0.100 |
| D：BM25 | direct | 0.200 | 0.100 | 0.100 |
| D | targeted | 0.500 | 0.300 | 0.050 |
| D | raw_targeted | 0.450 | 0.100 | 0.000 |
| D | generic | 0.400 | 0.200 | 0.150 |
| D | full_intent | 1.000 | 0.800 | 0.050 |

結論：C 的直接搜尋第一名命中率從 0.45 升至 targeted 與 raw_targeted 的 0.70。看原始 description 和看工作線卡產生的反問，結果相同，因此產品不需要依賴工作線卡。通用問題在部分條件也很好，不能把所有提升都歸因於候選差異分析。

限制：只有 20 條；回答由模型扮演使用者產生；full_intent 與補答後查詢的文字分布不同，不能保證每個 arm 的最佳名次都會隨資訊量增加；近誤率不會因增加正確答案而必然下降；沒有可用的分數門檻。

## 3. 作者那一側：改寫 description

將上游 description 分別保留原文、改成六槽自然段、以及加入通用寫作提示改寫。`original`、`sixslot`、`generic` 比較模型從候選描述中選擇正確 Skill 的能力，不是重新跑 embedding 索引。

75 條一般查詢：

| 描述版本 | 第一名命中率 | 近誤率 | 前三命中率 |
|---|---:|---:|---:|
| original | 0.880 | 0.040 | 0.987 |
| sixslot | 0.867 | 0.027 | 0.973 |
| generic | 0.893 | 0.040 | 0.987 |

20 條模糊查詢：

| 描述版本 | 第一名命中率 | 近誤率 | 前三命中率 |
|---|---:|---:|---:|
| original | 0.900 | 0.100 | 1.000 |
| sixslot | 0.800 | 0.200 | 1.000 |
| generic | 0.850 | 0.150 | 1.000 |

結論：六槽改寫沒有改善這個候選選擇任務；一般查詢的 sixslot 與 original 相比為 5 勝 6 敗，模糊查詢為 0 勝 2 敗。通用改寫也沒有提供可利用的一致優勢。因此六槽只能作為寫作檢查建議，不能宣稱能提升檢索或選擇效果。

限制：這一輪測的是模型看 description 後的選擇，不是六槽文字作為新 embedding 索引的效果；改寫品質與上游描述資訊量會影響結果；20 條模糊查詢的差異尤其容易受少量案例影響。
